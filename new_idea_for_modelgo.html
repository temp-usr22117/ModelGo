Android Local LLM App – System Architecture
Goal: Native Android app (minSdk 29 / Android 10+) that runs GGUF models fully on-device using llama.cpp.
Core Engine: llama.cpp (via NDK/JNI)
Primary Language: Kotlin + Jetpack Compose
Target Architecture: arm64-v8a

1. High-Level Layers

  1. Presentation Layer (UI)
  2. Domain Layer (Business Logic)
  3. Data Layer (Model Management & Storage)
  4. Native Inference Layer (llama.cpp)
  5. Platform Layer (Android System Services)

2. Module Structure (Recommended Multi-Module Project)

app/                          → Main application module (UI + navigation)
core/
  ├── domain/                 → Use cases, models, repository interfaces
  ├── data/                   → Repository implementations, local storage
  └── common/                 → Shared utilities, constants, result types
inference/
  ├── jni/                    → JNI bridge + CMakeLists
  └── llama/                  → llama.cpp source or prebuilt .so files
feature/
  ├── chat/                   → Chat screen + ViewModel
  ├── models/                 → Model browser / download / management
  └── settings/               → App settings, parameters, themes

3. Component Responsibilities

3.1 Presentation Layer

  • ChatScreen (Compose)
  • ModelListScreen
  • SettingsScreen
  • ModelDownloadProgress UI
  • ViewModels (ChatViewModel, ModelViewModel, SettingsViewModel)
  • Navigation (NavHost + sealed routes)

3.2 Domain Layer

  • Entities: ChatMessage, ModelInfo, InferenceConfig, GenerationResult
  • Use Cases:
    • LoadModelUseCase
    • UnloadModelUseCase
    • GenerateResponseUseCase (streaming)
    • ListLocalModelsUseCase
    • DownloadModelUseCase
    • DeleteModelUseCase
    • UpdateInferenceParamsUseCase
  • Repository Interfaces:
    • ModelRepository
    • ChatRepository
    • SettingsRepository

3.3 Data Layer

  • ModelRepositoryImpl (file system + Room/SharedPreferences)
  • ChatRepositoryImpl (Room database for conversation history)
  • SettingsRepositoryImpl (DataStore)
  • File storage location: context.filesDir/models/ (app-private)
  • Model metadata: name, size, quantization, context length, path, last used

3.4 Native Inference Layer

  • LlamaEngine (Kotlin singleton / interface)
    • loadModel(path, config)
    • unloadModel()
    • generate(prompt, params) → Flow (token streaming)
    • isLoaded(): Boolean
    • getModelInfo()
  • JNI Bridge (C++):
    • Java_…_nativeLoadModel
    • Java_…_nativeGenerate
    • Java_…_nativeUnload
    • Java_…_nativeIsLoaded
  • llama.cpp build configuration:
    • ANDROID_ABI = arm64-v8a
    • ANDROID_PLATFORM = android-29
    • GGML_OPENMP = OFF
    • Optional: GGML_VULKAN = ON or GGML_OPENCL = ON

3.5 Platform Layer

  • Storage Access Framework (for importing external GGUF files)
  • WorkManager (optional background model downloads)
  • Foreground Service (optional long-running generation)
  • Notification for download progress
  • WakeLock / thermal awareness (optional)

4. Data Flow (Happy Path)

  1. User selects or imports a GGUF model → ModelRepository saves metadata + file.
  2. User opens Chat → ChatViewModel calls LoadModelUseCase.
  3. LoadModelUseCase → LlamaEngine.loadModel().
  4. User sends message → GenerateResponseUseCase → LlamaEngine.generate() returns Flow of tokens.
  5. Tokens are collected in ViewModel and emitted to UI (streaming).
  6. Final response is saved via ChatRepository.
  7. On app background or explicit unload → UnloadModelUseCase.

5. Key Interfaces (Clean Contracts)

interface LlamaEngine {
    suspend fun loadModel(path: String, config: InferenceConfig): Result<Unit>
    fun unloadModel()
    fun generate(prompt: String, params: GenerationParams): Flow<String>
    fun isModelLoaded(): Boolean
    fun getLoadedModelInfo(): ModelInfo?
}

interface ModelRepository {
    fun getAllModels(): Flow<List<ModelInfo>>
    suspend fun addModel(file: File, metadata: ModelInfo)
    suspend fun deleteModel(id: String)
    suspend fun getModelPath(id: String): String?
}

data class InferenceConfig(
    val contextSize: Int = 2048,
    val threads: Int = 4,
    val gpuLayers: Int = 0
)

data class GenerationParams(
    val temperature: Float = 0.7f,
    val topP: Float = 0.9f,
    val topK: Int = 40,
    val maxTokens: Int = 512,
    val stopSequences: List<String> = emptyList()
)

6. Build & Native Integration Steps

  1. Create Android project with Kotlin + Compose (minSdk 29, targetSdk 35+).
  2. Add NDK + CMake support.
  3. Add llama.cpp as git submodule under inference/llama/.
  4. Write CMakeLists.txt that builds llama.cpp + custom JNI shared library.
  5. Create JNI bridge (.cpp) that exposes the required native methods.
  6. Load the .so library in Kotlin (System.loadLibrary).
  7. Implement LlamaEngine using the JNI methods.
  8. Wire everything through Hilt / Koin (recommended for clean DI).

7. Non-Functional Requirements

  • Fully offline after model download
  • No INTERNET permission required at runtime (optional only for model download)
  • Memory-safe: always unload model when not in use
  • Streaming responses (token-by-token)
  • Support importing any GGUF file
  • Persist chat history locally
  • Configurable generation parameters
  • Graceful error handling (OOM, invalid model, etc.)
